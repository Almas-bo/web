Objective: Extend the existing responsive sneaker store with interactive JavaScript features that demonstrate DOM manipulation, event handling, data structures, callbacks, sound, and animation.

Implementation steps

  1. DOM manipulation and styling. The shared js/main.js selects elements with querySelector/querySelectorAll, updates messages and counts, changes form classes and FAQ height, switches the day/night CSS class, and updates star-rating attributes. The home-page stars respond to clicks and visibly show the selected rating.
  2. Catalog filter and switch statement. Product cards expose price and status data attributes. JavaScript builds an array of product objects and filters it with Array.filter(). A switch handles All, New, Sale, and Under $140 choices, and the visible item count updates immediately.
  3. Events and keyboard access. Buttons and forms use addEventListener. Arrow keys move focus through navigation links; Home and End focus the first and last link. Contact validation shows an asynchronous callback response without reloading. Its response is explicitly a local demo and does not send email to a server.
  4. Objects, arrays, and reusable functions. Product objects hold each card's data. Validator objects and arrays organize form rules, and reusable functions handle validation, messages, filtering, and updates. map, filter, and forEach demonstrate higher-order iteration.
  5. Sound and animation. Cart actions and star ratings trigger a short Web Audio tone. A single oscillator is stopped before another begins, preventing overlapping sounds. Adding an item triggers a CSS card animation and an accessible live notification.
  6. Structure and user experience. HTML, CSS, and JavaScript remain in separate files. The theme toggle, status messages, accessible labels, responsive Bootstrap layout, and reduced-motion CSS improve usability.

Challenges and reflection

The existing project had no server endpoint for contact or account registration. Rather than claim that messages were delivered or accounts created, the interface now clearly identifies those responses as front-end demonstrations. The project keeps data local to the page and remains deployable as a static site. Testing the filters and keyboard behavior helped catch and verify the exact visible results.
